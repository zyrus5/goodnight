# Jenkins Job 统一编排平台 PRD

## 1. 文档信息

- 产品定位：统一管理分散在不同客户、部署域和环境中的多个 Jenkins Job，并按依赖关系编排、调度、执行和追踪。
- 本期范围：组件、客户、环境/Jenkins 连接、组件实例、Job 配置、任务编排、调度、执行记录、日志、权限和审计。
- 非本期范围：替代 Jenkins 的 CI/CD 能力、编辑 Jenkins Pipeline、代码仓库管理、制品管理、跨任务传递 Jenkins 输出参数、审批流。

## 2. 背景与目标

不同客户、部署域和环境分别部署 Jenkins。例如：

- 联华客户包含“鲸选”“拉普”两个部署域，每个部署域包含测试、验收和生产环境。
- 振华客户不区分部署域，仅包含测试、验收和生产环境。

当前用户需要分别进入多个 Jenkins 查找并执行 Job，难以统一编排、控制权限和追踪结果。本系统需要：

1. 统一维护多个 Jenkins 连接及其 Job。
2. 将 Jenkins Folder 绑定为业务组件在特定环境下的“组件实例”。
3. 将多个 Job 组织为无环依赖图（DAG），支持串行、并行及其组合。
4. 支持立即、指定时间和周期调度，并可靠追踪 Jenkins 排队与构建状态。
5. 提供权限控制、敏感信息保护、操作审计和可追溯的执行快照。

## 3. 核心概念

| 概念     | 定义                                                   |
|--------|------------------------------------------------------|
| 组件     | 业务微服务或可独立发布单元，不区分客户、部署域和环境。                          |
| 客户     | 系统交付或部署的客户主体。                                        |
| 部署域    | 同一客户下相互隔离的部署范围，可为空。                                  |
| 环境     | 客户 + 部署域 + 环境代码所确定的部署环境，并关联一个 Jenkins 连接。            |
| 组件实例   | 某组件在某环境中对应的 Jenkins Folder。一个 Folder 在同一环境下最多绑定一个组件。 |
| Job 配置 | 从组件实例中选择的 Jenkins Pipeline Job，以及用户保存的显示名称和参数预设。     |
| 任务     | 一份可执行的 Job 编排定义，包括节点、依赖、参数、触发方式和执行策略。                |
| 执行记录   | 任务每次触发产生的不可变运行快照。周期任务每次触发都会生成独立记录。                   |

组件实例的 Jenkins Folder 中通常包含修改版本号、部署（含/不含数据库升级）、单独执行数据库升级等 Job，但系统不硬编码 Job
名称或用途。

## 4. 用户与权限

### 4.1 系统角色

| 角色    | 权限                                    |
|-------|---------------------------------------|
| 系统管理员 | 管理用户、客户、环境、Jenkins 凭据及全部组件；查看和操作全部任务。 |
| 普通用户  | 仅在被授权组件范围内查看实例、配置 Job、创建和操作任务。        |

### 4.2 组件角色

| 角色     | 权限                                                      |
|--------|---------------------------------------------------------|
| 组件维护人员 | 修改组件信息和成员；绑定/解绑组件实例；新增、修改、删除 Job 配置；创建和执行任务。            |
| 组件测试人员 | 查看组件、实例和 Job 配置；使用已配置的 Job 创建和执行任务；不能修改组件、绑定关系或 Job 配置。 |

规则：

- 组件角色默认适用于该组件的所有客户、部署域和环境。
- 一个用户可同时拥有多个组件角色，按权限并集计算。
- 任务包含多个组件时，用户必须对所有节点所属组件拥有“创建和执行任务”权限。
- 客户、环境和 Jenkins 凭据仅系统管理员可维护。
- 所有配置变更、任务启停、手工重试等操作记录操作者、时间、对象和变更摘要。

> 首版可接入现有登录体系；若暂无统一认证，必须先实现本地用户登录，不允许匿名访问。

## 5. 功能需求

### 5.1 组件管理

#### 列表

- 筛选：组件代码或名称模糊查询。
- 字段：代码、名称、维护人员、测试人员、实例数量、更新时间。
- 组件代码全局唯一，创建后不可修改。

#### 创建和修改

- 创建时填写组件代码、名称，选择至少一名维护人员，可选择测试人员。
- 修改时允许修改名称、维护人员和测试人员，不允许修改代码。
- 删除前必须确认不存在组件实例、Job 配置或未结束的关联任务；否则禁止删除。建议默认停用而非物理删除。

### 5.2 客户管理

#### 列表

- 筛选：客户代码或名称模糊查询。
- 字段：代码、名称、环境数量、状态、更新时间。
- 点击客户名称进入环境管理，并自动带入客户筛选条件。
- 客户代码全局唯一，创建后不可修改。

#### 创建和修改

- 创建时填写客户代码和名称。
- 修改时允许修改名称和启用状态，不允许修改代码。
- 存在环境或未结束任务时禁止删除；停用客户后禁止新建相关任务，但不影响历史记录查看。

### 5.3 环境与 Jenkins 连接管理

#### 列表

- 筛选：客户下拉、部署域模糊查询、环境代码或名称模糊查询、启用状态。
- 字段：客户（代码 + 名称）、部署域、环境代码、环境名称、Jenkins 地址、连接状态、最后检测时间、启用状态。
- 唯一键：客户 + 标准化后的部署域 + 环境代码。空部署域统一按空字符串处理。
- 环境代码创建后不可修改；客户和部署域在未绑定组件实例时可修改，已有绑定后禁止修改，以避免业务标识漂移。
- 环境名称不可链接到自身；点击客户进入该客户的环境列表，点击环境名称进入环境详情。

#### 创建和修改

- 必填：客户、环境代码、环境名称、Jenkins 根地址、认证方式和凭据。
- 可选：部署域、请求超时、自签名证书配置、备注。
- 环境代码建议使用 `test`、`uat`、`prod`，但允许管理员维护其他代码。
- Jenkins 地址必须是 `http` 或 `https`，保存时去除末尾 `/`。
    - 认证通过程序启动时，在env文件中填写用户名和密码来获取
    - 调用jenkins一些需要token认证的接口时，使用jenkins的Crumb来认证
- 保存前执行连接测试：调用 Jenkins API 验证地址、凭据和权限，并显示明确错误。连接测试失败时允许管理员“仍然保存为停用状态”，不允许直接启用。
- 服务端必须限制 Jenkins 目标地址范围并阻止访问本机、云元数据等非授权地址，避免 SSRF；生产环境默认要求
  HTTPS，关闭证书校验需要显式警告和审计。
- 修改 Jenkins 地址或凭据后必须重新测试；测试通过前禁止新任务使用该环境。

#### 复制环境

- 从环境列表点击“复制”，进入创建页并带入客户、部署域、环境名称、连接配置等作为初始值。
- 环境代码必须重新确认。

#### 连接检测

- 支持手工检测连接。
- 系统定期检测已启用环境，并保存最后成功时间和最近错误摘要；连续失败不自动删除配置。

### 5.4 绑定组件实例

从环境详情点击“绑定组件”：

1. 系统从 Jenkins 根节点开始递归读取 Folder。Jenkins View 仅作为展示分组，不能假定 View 下返回的对象一定是 Folder。
2. 支持 Jenkins Folder、多层嵌套 Folder，以及根目录下的 Folder；对无访问权限的节点显示不可访问，不中断其他节点加载。
3. 用户选择一个 Folder 并绑定一个组件，即创建组件实例。
4. 保存 Jenkins Folder 的稳定全名（full name）及相对路径；URL 仅作为最近一次发现结果保存，不能作为唯一标识，因为 Jenkins 地址或
   Folder 名称可能变化。
5. 同一环境下，同一 Folder 只能绑定一个组件；同一组件可在同一环境绑定多个 Folder，但实例名称必须不同。

组件实例字段：实例名称、组件、环境、Jenkins Folder 全名、状态、备注、自定义信息、最后同步时间。

- 自定义信息为若干“名称 + 值”项目；名称在实例内唯一，URL 类型应可点击。
- 支持刷新、停用和解绑。解绑前若存在未结束任务则禁止操作；历史执行记录保留绑定时快照。
- Folder 不存在或无权访问时标记实例异常，不自动删除。

### 5.5 Job 配置管理

从组件实例点击“Job 管理”：

1. 系统递归查询实例 Folder 下的 Job，首版仅支持 Jenkins Pipeline Job（`WorkflowJob`），并显示完整路径。
2. 用户选择 Job 后，系统读取参数定义，包括参数名、类型、默认值、选项和描述。
3. 用户保存 Job 显示名称、说明和参数预设。显示名称在同一组件实例内唯一。

首版参数类型：

- String、Text、Choice、Boolean、Password。
- 不支持的参数类型需明确标记，含不支持参数的 Job 不允许保存或执行，不得静默忽略。
- Password 参数加密存储、页面掩码展示、日志和审计中脱敏；复制任务时不复制其明文值，执行前需重新填写。
- File 参数首版不支持。

同步与变更处理：

- 每次进入编辑页及执行前都从 Jenkins 拉取最新定义，并与已保存定义比较。
- 新增、删除、改名、类型变化、Choice 选项失效属于不兼容变更，必须阻止执行并要求用户更新配置。
- 仅默认值变化时，显示差异并允许逐项选择“保留预设值”或“使用 Jenkins 新默认值”。选择结果保存为新的配置版本。
- Jenkins Job 用环境 + 完整路径标识。Job 被重命名或删除后标记异常，不自动匹配其他同名 Job。
- 修改和删除 Job 配置需要组件维护人员权限；存在未结束任务引用时禁止删除，可改为停用。

### 5.6 任务中心

#### 5.6.1 任务列表

- 筛选：任务名称、客户、部署域、环境、组件、创建人、触发方式、状态、计划时间范围。
- 字段：任务名称、触发方式、最近/计划执行时间、运行状态、创建人、更新时间、操作。
- 可查看任务定义、执行历史和每个节点的 Jenkins 链接、状态及日志。

#### 5.6.2 创建和编辑任务

页面分为左右两部分：

- 左侧为有权限且已启用的 Job 配置列表，支持按客户、部署域、环境、组件和 Job 名称筛选。
- 右侧为编排画布/分层列表。节点间通过“前置节点”定义依赖关系；无依赖节点并行执行，有依赖节点在所有前置节点成功后执行。

任务字段：

- 名称、说明。
- 一个或多个 Job 节点；同一 Job 可添加多次，但每个节点必须有唯一名称。
- 节点参数。初始值来自 Job 参数预设，允许在权限范围内修改。
- 节点依赖。系统必须校验不存在环、悬空依赖或空任务。
- 节点超时时间；可继承系统默认值。
- 触发方式：立即执行、指定时间执行、周期执行。
- 失败策略首版固定为“阻断下游”：任一节点失败后，其依赖节点标记为 `SKIPPED`；已运行节点继续执行，其他不依赖失败节点的分支继续执行。整个执行最终为失败。

任务保存时保存引用的 Job 配置版本；每次触发时再生成包含实际参数（敏感值除外）、Job 完整路径及依赖关系的不可变执行快照。修改任务只影响后续执行，不影响历史记录。

#### 5.6.3 调度规则

- 立即执行：保存并立即创建一次执行记录。
- 指定时间：计划时间必须晚于当前时间；到时创建一次执行记录。
- 周期执行：使用标准 5 段 Cron 表达式，并必须选择时区，默认 `Asia/Shanghai`；页面提供未来 5 次执行时间预览。
- 周期任务可启用、暂停和恢复。修改 Cron 仅影响未来触发。
- 服务重启后的漏执行策略：指定时间任务补执行一次；周期任务不补历史次数，只计算下一次时间，并记录一次“错过调度”事件。
- 同一周期任务不允许重叠执行：上一次未结束时跳过本次触发并记录原因。

#### 5.6.4 执行流程与 Jenkins 关联

每个可运行节点按以下流程执行：

1. 执行前再次检查环境、组件实例、Job 配置和 Jenkins 连接状态，并校验最新参数定义。
2. 按 Jenkins 配置获取 CSRF Crumb（Jenkins 未启用时兼容无 Crumb）。
3. 调用 `buildWithParameters`；无参数 Job 调用 `build`。
4. 从响应 `Location` 获取 Jenkins queue item URL/ID，并持久化。禁止通过“最新构建号”猜测本次构建。
5. 轮询 queue item：排队时状态为 `QUEUED`；若被 Jenkins 取消则标记 `CANCELED`；获得 `executable.number/url` 后保存准确的
   build number 和 URL，状态变为 `RUNNING`。
6. 轮询构建结果直至结束，并映射 Jenkins 结果。成功后释放下游节点；失败、终止、超时或未知结果均按失败处理。
7. Jenkins 请求采用有限次数指数退避。短暂网络故障显示 `UNKNOWN` 并继续查询；超过节点超时后标记 `TIMED_OUT`
   ，不得自动重复触发构建，避免重复发布。

系统应设置全局及单 Jenkins 并发上限；超过上限的节点在本系统内等待，不占用 Jenkins queue。Jenkins 自身阻塞原因（如等待执行器）应展示给用户。

#### 5.6.5 状态模型

节点状态：

`PENDING` → `WAITING_DEPENDENCY` / `QUEUED` → `RUNNING` → `SUCCESS` / `FAILED` / `CANCELED` / `TIMED_OUT` / `UNKNOWN`

未执行的失败下游节点为 `SKIPPED`。

执行记录状态：

- `SCHEDULED`：等待计划时间。
- `RUNNING`：至少一个节点已提交或运行，或仍有可继续的节点。
- `SUCCESS`：所有节点成功。
- `FAILED`：任一节点失败、超时、最终未知或被跳过，且执行已结束。
- `CANCELING`：正在向 Jenkins 请求取消。
- `CANCELED`：用户取消且所有节点均已终止或不再执行。

状态必须持久化；服务重启后恢复对 `QUEUED`、`RUNNING`、`UNKNOWN` 节点的查询，不得重新提交 Job。

#### 5.6.6 日志

- 运行中通过 Jenkins progressive log API 增量读取日志；不应反复全量请求 `consoleText`。
- 支持查看每个节点日志和 Jenkins 原始构建页面，不将多个并行节点日志混成单一时间线。
- Jenkins 日志被清理或无权限时，显示“日志不可用”及原因，不影响已保存的执行结果。
- 页面展示前对已知 Password 参数、Token 等敏感信息做脱敏；系统自身日志不得记录 Jenkins 凭据和完整敏感参数。
- 首版不保证永久保存 Jenkins 全量控制台日志，仅保存状态、时间、构建链接和错误摘要；如需长期归档应另立存储需求。

#### 5.6.7 停止任务

- `SCHEDULED` 状态可直接取消，不再触发。
- `RUNNING` 状态允许停止。系统立即阻止提交新节点，并对 Jenkins queue item 调用取消接口、对已运行 build 调用停止接口。
- Jenkins 停止为尽力而为：失败时任务保持 `CANCELING` 并继续同步真实状态，同时明确提示未能停止的节点；不能向用户承诺一定终止远端构建。
- 已结束任务不能停止。

#### 5.6.8 重试与复制

- 允许对已结束执行进行“复制为新任务”，带入编排、非敏感参数和执行策略，触发方式固定为立即执行；用户确认后才执行。
- 首版不提供单节点原地重试，避免部分部署造成不可预测状态。需要重跑时复制任务，用户可删除不需要的节点或调整依赖和参数。
- 历史执行记录和快照不可修改或删除；按系统数据保留策略归档。

## 6. 异常与边界规则

- Jenkins 不可达：禁止新提交，已提交节点进入 `UNKNOWN` 并按超时规则持续同步。
- Jenkins 返回未授权：立即停止该节点的后续请求，标记错误并通知管理员检查凭据/权限。
- Folder 或 Job 消失：实例/Job 配置标记异常，禁止新任务使用；历史任务仍可查看。
- Jenkins 重启或 queue item 被清理：若已记录 build URL/number，继续按构建查询；否则不能确认是否已触发时标记 `UNKNOWN`
  ，禁止自动重提。
- 用户重复点击执行：前端禁用重复提交，服务端使用幂等键保证同一次请求最多创建一条执行记录。
- 参数校验：Choice 必须属于最新选项，Boolean 只能为布尔值；所有参数均受长度限制。服务端最终校验，不依赖前端。
- 时间统一以 UTC 存储，按任务所选时区展示和计算调度。

## 7. 非功能需求

### 7.1 安全

- Jenkins API Token、Password 参数等敏感数据必须加密存储，密钥通过部署环境注入并支持轮换。
- API 全部鉴权并执行服务端权限校验；不能只通过隐藏前端按钮控制权限。
- 防止 SSRF、路径注入、日志注入和敏感信息泄露。
- 生产变更的二次确认或审批流不在首版范围，但执行生产环境 Job 前必须展示醒目标识并二次确认。

### 7.2 可靠性

- 调度器在多实例部署时必须通过数据库锁或 leader election 保证同一触发只执行一次。
- Job 提交、状态更新和调度触发均需幂等。
- 服务重启后可恢复调度和执行状态追踪。

### 7.3 性能与可观测性

- 列表查询分页，默认每页 20 条。
- Jenkins API 调用设置连接/读取超时、并发限制和退避策略，不能因单个 Jenkins 卡住整个任务。
- 记录任务数、排队时长、执行时长、成功率、Jenkins 请求错误率等指标，并为调度失败和长期 `UNKNOWN` 状态告警。

## 8. 首版验收标准

1. 管理员可配置至少两个不同 Jenkins，验证连接并分别发现多层 Folder 和 Pipeline Job。
2. 可将不同环境中的 Folder 绑定到组件，并按权限限制实例和 Job 配置的维护及使用。
3. 可创建包含串行、并行及混合依赖的任务；系统能拒绝循环依赖。
4. 立即、指定时间、周期三种触发均能创建唯一执行记录；周期任务不重叠。
5. 能准确保存 Jenkins queue ID、build number 和 build URL，并展示排队、运行和最终状态。
6. 任一节点失败时其下游不执行，独立分支继续，最终任务状态为失败。
7. 服务重启后不会重复提交已触发 Job，并能继续追踪远端状态。
8. 可查看节点级增量日志；Jenkins 日志被清理时给出明确提示。
9. 可停止未执行任务，并对已排队/运行 Jenkins 构建执行尽力取消，页面展示真实结果。
10. Jenkins Token 和 Password 参数不以明文存储、展示或写入系统日志。
11. 修改 Jenkins 参数定义后，系统能识别不兼容变更并阻止错误执行。
12. 所有关键配置变更和任务操作均可按操作者、对象和时间审计。

## 9. 默认产品决策

为消除实现歧义，首版采用以下默认决策：

- 编排模型使用 DAG，不支持条件分支和节点输出参数传递。
- 失败策略固定为阻断失败节点的下游，独立分支继续执行。
- 停止远端 Jenkins 构建采用尽力而为语义。
- 周期任务采用 5 段 Cron + 显式时区，不补跑错过的周期。
- 同一周期任务禁止重叠执行。
- 不自动重试 Jenkins 构建；网络状态不明时宁可标记 `UNKNOWN`，也不重复发布。
- Jenkins 全量控制台日志不做永久归档，仅按需读取并保存执行元数据。
